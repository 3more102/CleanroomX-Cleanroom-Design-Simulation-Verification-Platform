# CleanroomX evidence-grounded project assistant

The first read-only assistant slice adds a deterministic **project evidence reviewer**
to the existing multi-agent architecture. It does not yet connect to an LLM
provider or control OpenFOAM, geometry, hardware, or engineering decisions.

## Quick start

Install the repository in editable mode, then inspect a saved project:

```powershell
python -m pip install -e .
cleanroomx-assistant "C:\\path\\to\\facility.cleanroomx.json" --format markdown
cleanroomx-assistant "C:\\path\\to\\facility.cleanroomx.json" --format json --max-findings 20
```

You can also use `python -m cleanroomx.assistant_review_cli project.cleanroomx.json`.

The `--question` argument is retained in the structured report and the
multi-chat agent record; this **is not currently a natural-language reasoning or
filtering command**. The output is the priority-ordered diagnostics report,
rather than an invented free-form response.

Return codes: 0 = no error/warning diagnostic findings; 1 = at least one
error/warning; 2 = invalid project, rejected revision, or other inspection error.
Code 0 **never certifies a cleanroom or proves CFD convergence**.

## Supported engineering workflow

1. Load an existing `ProjectDocument` together with its exact byte revision.
2. Validate that the source revision still matches before diagnostics.
3. Run the canonical `analyze_project_diagnostics()` with project-relative input paths.
4. Reject any change to project bytes during diagnostics (fail closed).
5. Prioritize canonical issues: errors, warnings, then information; preserve original
   diagnostic sequence and rule names for cross-reference.
6. Return a bounded, strict-JSON review with source SHA-256, severity counts,
   verification-currency summary, required actions and limitations.
7. Optionally present the review as safe Markdown.

No solver results, qualification limits, acceptance thresholds or CFD data are
generated by the assistant. It does not repair source files or automatically
execute analyses. Retained historical verification is not silently treated as
current verification.

## Multi-agent integration

```python
from cleanroomx.multi_agent import ChatSessionStore, MultiAgentCoordinator
from cleanroomx.assistant_review import register_project_review_agent

store = ChatSessionStore()
store.create_session("engineering-chat", "Engineering review")
coordinator = MultiAgentCoordinator(store)
register_project_review_agent(
    coordinator,
    "evidence-review",
    project_path="facility.cleanroomx.json",
)
batch = coordinator.run(
    "engineering-chat",
    "Identify project diagnostics requiring corrective action.",
    agent_ids=["evidence-review"],
)
```

The response is an `AgentReply` with human-readable Markdown and a versioned
strict-JSON data payload. The existing coordinator supplies session isolation,
deterministic batch ordering, optimistic revision handling and transcript receipt
integrity. Any future provider-backed model should consume this bounded evidence
and must not be allowed to rewrite or overrule its validation states.

## Current boundaries and next integration stage

- There is **no LLM API client, conversation GUI, or autonomous write access** in
  this first slice. A future GUI can call the same reviewer in a background
  worker, displaying source and validation status without blocking Tk.
- This is *project-model* diagnostics, not a claim of genuine OpenFOAM mesh,
  solver convergence, validated particle transport, calibrated contamination
  or ISO certification.
- SHA-256 confirms exact source bytes for the review but does not authenticate
  their author or establish physical correctness.
- For CFD claims, use the existing canonical imported real-solver evidence,
  convergence reports and qualification workflows; never substitute model prose.

Focused tests: `pytest -q tests/test_assistant_review.py`.
